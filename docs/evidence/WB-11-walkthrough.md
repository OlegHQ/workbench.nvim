# WB-11 terminal walkthrough

Reproduce with `make test-e2e`. This runs the real RPC-grid walkthrough on Neovim 0.11.7 and the current host Neovim at 160x50, 120x35, 80x24 and 60x20. The 60x20 layout becomes an overlay. The harness starts isolated `--clean` child instances, creates real A/B filesystem fixtures, attaches `ext_linegrid`, sends keyboard/mouse input and records grids plus final state under `.test-output/e2e/wb11/`.

The combined path begins with a modified editor buffer and editor cwd in folder B. Open Files; use `j`/`l` to expand A, click B and expand it, then click and press Enter on a file in A. Both branches remain expanded and the modified editor text survives. `<C-^>` returns to the original editor buffer. Select A and press `s`; the empty Search shell appears without changing cwd. Enter `/needle`: real ripgrep returns 110 matches scoped to A, including a generated 100-line file. Previewing the modified-buffer match leaves its unsaved content intact and adds no preview jumplist entry. Press `o` to open, then `R` to return; close and reopen Search with `q` and the same query, result identity and selection resume.

Open a second tab and search B. Actual prompt input issues `ux03-first`, `ux03-second`, and `ux03-latest`; the first response is delivered last and rejected. Switch tabs to verify A's and B's scope/query/selection remain separate. Start another pending request and close that tab; a deliberately delivered late batch is rejected and the first tab remains live. Closing both views and disposing their controllers/providers leaves zero Search views, Files sessions, layout views, ripgrep requests and filesystem requests; both modified editor buffers remain unchanged.

Coverage is split across the checkpoint suites: UX-01..04, UX-05's search/preview/open/return/resume portion, UX-06, UX-09 and UX-11 are asserted in the combined real-grid path and WB-10 Search path; UX-07 is exercised by the three-cycle scoped capability/autocmd test in `tests/runtime/test_core_actions.lua`; UX-08 is exercised by the missing-rg Search action/palette tests and 100 repeated unavailable-view open/close cycles in `tests/runtime/test_search_controller.lua`. The general lifecycle UI suite additionally verifies rendered idle/loading/empty/error/unavailable states, actual mouse/keyboard interaction, 100 view mount/close cycles, foreign autocmd preservation and zero residual resources.

Public-boundary review: `require('workbench')` is the lazy package facade (`setup`, `execute`, `register_capability`, `get_status`, and `command`); `plugin/workbench.lua` registers only the cheap `:Workbench [status]` command. Files/Search controllers receive providers and services by injection and do not load through that host command yet. This checkpoint validates them in isolated controller composition; default host mappings/autoconf adapter and Nix installation remain WB-25 work. No production Lua, startup, theme or Nix path changed for WB-11.

On the eight full WB-11 runtime/grid runs, Files root-to-first-page took 19.377–24.836 ms, Search shell invocation 3.117–10.586 ms, and folder-search input-to-completion for 110 results 92.667–102.131 ms. The host startup comparison is the WB-10 interleaved profile: marker p50/p95 44.120/51.356 ms against WB-09 43.745/44.236 ms, a +0.375/+7.120 ms delta. WB-11 changes are tests, harness wiring and evidence only, so they do not add runtime startup work.

All local evidence is from macOS arm64 (Neovim 0.11.7 and 0.12.4). Linux was not available in this environment; the broader release's Linux platform check remains outstanding.
